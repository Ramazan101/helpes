# Help Desk — Внутренняя система технических заявок («Кыргыз Алтын»)

**Help Desk** — адаптивное веб-приложение для быстрой регистрации неисправностей оборудования сотрудниками и обработки заявок технической службой компании «Кыргыз Алтын».

## 1. Назначение и архитектура

Система разделена на три независимых интерфейса:
1. **Интерфейс сотрудника (`/`)** — открытая форма подачи заявки без регистрации и пароля, адаптированная для смартфонов и ПК. Позволяет указать имя, кабинет (или произвольное местоположение), одну или несколько категорий оборудования с количеством и описание проблемы. Присваивает уникальный номер вида `HELP-000124`.
2. **Интерфейс технического специалиста (`/tech/queue/`)** — защищённая авторизацией рабочая очередь. Позволяет просматривать новые обращения, безопасно забирать свободные заявки в работу (с защитой от одновременного взятия двумя техниками), менять статусы (`Новая`, `В работе`, `Ожидает`, `Выполнена`), вести диагностические комментарии и фиксировать результат ремонта.
3. **Интерфейс администратора (`/manage/tickets/`)** — панель диспетчеризации и настройки справочников. Позволяет назначать и переназначать заявки, отслеживать зависшие обращения, управлять учётными записями техников (с безопасным перераспределением открытых задач при отключении сотрудника), а также динамически добавлять и архивировать здания, этажами, кабинетами и категориями оборудования без изменения кода.

## 2. Быстрый локальный запуск (из чистого окружения)

```bash
cd helpes
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py seed_initial_data
python manage.py createsuperuser
python manage.py runserver
```

После создания суперпользователя зайдите в `/accounts/login/` и при необходимости установите роль `ADMIN` или создайте учётные записи техников через `/manage/users/`.

## 3. Руководство по настройке справочников

1. **Этажи и кабинеты (`/manage/locations/`):** добавьте этажи (при необходимости — корпуса/здания), затем привяжите к ним кабинеты. При переименовании или отключении кабинета старые заявки сохраняют историю.
2. **Категории оборудования (`/manage/categories/`):** команда `seed_initial_data` создаёт 7 базовых категорий. Администратор может добавлять новые категории, менять порядок сортировки и скрывать неактуальные.
3. **Учётные записи техников (`/manage/users/`):** создавайте техников с ролью `TECH`. При увольнении или болезни используйте кнопку «Отключить» — система покажет открытые заявки специалиста и предложит переназначить их другому технику или вернуть в общую очередь.

## 4. Резервное копирование и восстановление

### PostgreSQL (производственный сервер)
```bash
# Создание резервной копии
pg_dump -U helpes_user -h 127.0.0.1 -F c -f backup_helpes_$(date +%F).dump helpes_db

# Восстановление из резервной копии
pg_restore -U helpes_user -h 127.0.0.1 -d helpes_db --clean backup_helpes_YYYY-MM-DD.dump
```

### SQLite (локальная среда)
```bash
sqlite3 db.sqlite3 ".backup 'backup_helpes_$(date +%F).sqlite3'"
```

## 5. Подготовка к развёртыванию на внутреннем сервере «Кыргыз Алтын»

1. В файле `.env` установите `DJANGO_DEBUG=False`, задайте криптографически стойкий `DJANGO_SECRET_KEY`, укажите внутренний IP/хост сервера в `DJANGO_ALLOWED_HOSTS` и `DJANGO_CSRF_TRUSTED_ORIGINS`, переключите `DB_ENGINE=postgresql` и пропишите реквизиты БД.
2. Выполните сборку статики и миграции:
   ```bash
   python manage.py migrate --noinput
   python manage.py collectstatic --noinput
   python manage.py seed_initial_data
   ```
3. Запустите приложение за Nginx через Gunicorn (`gunicorn config.wsgi:application --bind 127.0.0.1:8000 --workers 3`).

## Docker Compose (Help Desk)

Для локального запуска через Docker понадобятся Docker Engine и Docker Compose Plugin.

```bash
cp .env.example .env
# Перед запуском проверьте .env. Для AWS замените секретный ключ, пароль БД и разрешённые хосты.
docker compose config
docker compose up -d --build
docker compose ps
docker compose logs -f web
```

Откройте `http://localhost/`. Создание администратора: `docker compose exec web python manage.py createsuperuser`.

PostgreSQL доступен только во внутренней сети Docker, порт `5432` наружу не публикуется. Перед реальным использованием на AWS настройте HTTPS и только затем установите `DJANGO_SECURE_COOKIES=True`. Подробная инструкция: `DEPLOY_AWS_EC2.md`.
